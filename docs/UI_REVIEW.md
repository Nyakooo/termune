# 界面结构与验收记录

[返回项目首页](../README.md) · [使用指南](USAGE.md)

本文记录 Termune 当前终端界面的结构约定和人工验收重点。它不是自动化测试通过报告；终端字体、窗口尺寸、操作系统终端实现和真实播放场景仍需要在目标环境中检查。

## 当前界面

Termune 当前提供四种专业布局：

| 布局 | 设计方向 |
| --- | --- |
| Airwave | 留白较多，突出播放器和曲库 |
| Operations | 分栏式工作布局 |
| Tracker | 信息密集的曲库列表 |
| Btop | 顶部媒体信息与下方曲库概览 |

另有极简模式，保留曲库和基本播放控制。布局切换、主题、语言及显示模式可在设置中调整。具体操作以[使用指南](USAGE.md#界面与设置)为准。

## 交互约定

- 播放控制集中在播放器区域，不在曲库区域重复呈现。
- 歌词只在当前布局指定的位置展示；极简模式不展示歌词。
- 登录、搜索、设置和确认弹窗应接管当前输入焦点，避免误触发曲库快捷键。
- 鼠标操作与键盘操作应保持一致的状态结果。
- 窄终端优先使用紧凑布局，不应让主要播放和导航操作无法访问。
- 颜色、主题和中英文切换不应改变功能行为。

## 人工验收清单

在准备发布界面相关变更时，建议至少检查：

1. 四种专业布局和极简模式均可正常进入、退出。
2. 五种主题下文字、选中项、边框和提示均有足够对比度。
3. 窄终端尺寸下没有关键控件被永久遮挡。
4. 登录、搜索、设置和确认弹窗中的输入不会误触发全局快捷键。
5. 歌词跟随、手动浏览、恢复跟随和进度跳转行为一致。
6. 播放中切换布局、主题或语言，不会意外停止播放或重置进度。
7. 键盘和鼠标均能完成常用曲库导航与播放控制。

## 自动化预览

可以使用 Ratatui TestBackend 导出界面预览，供代码审查时对比布局变化：

```sh
TERMUNE_UI_CAPTURE_DIR=/tmp/termune-ui cargo test --bin termune export_ui_previews -- --ignored
```

预览用于检查终端字符布局，不等同于真实终端的字体、颜色、鼠标事件或音频设备验收。发布前仍应在目标操作系统和常用终端中进行实际检查。

## 验收边界

自动化渲染测试可以发现布局回归，但不能代替真实终端使用。真实 NAS 的歌词数据、音频设备行为、不同终端模拟器的鼠标支持及用户个人主题体验，都需要结合实际环境验证。不要仅凭静态截图或合成数据宣称所有环境均已通过。
